# PLAN - Fallout 4 Forge 0.1.0

Work order for the builder. Read this file, `STATE.md` and the git-ignored `LOCAL.md` (path
tokens such as `<GAME>`, `<TOOLS_ROOT>`, `<PATTERN>`, installed facts, verified tool pins).
Nothing else from the planning session is needed.

## Goal

A local-first toolkit that lets an agent make, check, package and ship any kind of Fallout 4
mod from a cold start: one CLI (`f4forge`), JSON on every command, facts read from the
installed game, a pinned tool set downloaded into one tools folder, one agent skill, and
self-registration with the Ultimate AI Starter Bundle. Finished means: installed and wired on
this PC, `f4forge doctor` exit 0, public MIT repository `SenjuWoo/Fallout4-Forge` with a
verified `v0.1.0` release.

## Rules for the builder

- One milestone per session (M0 and M1 together in the first), tasks in table order. After each task: fill Evidence, set Status
  `done`, update NEXT ACTION in STATE.md. A task whose Verify did not run is not `done`.
- Port, do not invent: `<PATTERN>` (same owner, MIT) is the template for `cli.py`, `util.py`,
  `doctor.py`, `knowledge.py`, `project.py`, `check.py`, `package.py`, `deploy.py`,
  `Install.ps1`, `Uninstall.ps1`, launchers, workflows and the test runner. Copy the shape,
  rename, then change only what Fallout 4 needs. `<PATTERN_LOCK>` is the template for the
  tool lock and sync.
- A fact about the game, a format or a framework enters `knowledge/facts.json` only with a
  tier and a source: `installed` (read from this install by a command), `primary` (official
  doc or upstream source file, with URL and commit or date), `secondary`, or `unverified`.
  `check` and validators never enforce an `unverified` fact as an error.
- Tests use synthetic fixtures only. No game file, nothing extracted from one, and no
  third-party mod file is ever committed. Installed-truth checks run on this PC and are
  recorded as Evidence, not as CI tests.
- Tracked files carry no drive letter, user name or machine path (T35 adds the test). Machine
  detail goes in `LOCAL.md`.
- The game folder, its Data, mod-manager staging, saves, INIs and other forges are read-only.
  The only writers into the game are the explicit `f4forge deploy` and the `f4forge ck`
  commands, each dry run until `--approve`.
- Paths contain spaces, `!` and parentheses: argv lists, never shell strings; every `.bat` and
  `.cmd` starts with `setlocal EnableExtensions DisableDelayedExpansion`. `.bat`/`.cmd`/`.ps1`
  are CRLF, everything else LF.
- Commits use the operator's git identity and carry no AI attribution line.
- Before the first download of a tool not yet on this PC: check its source and licence and
  append one verdict line to `<PROFILE>\SAFE-TOOLS.md` (reuse an existing matching verdict).
- Effort: Opus High for T11-T13, T15-T18, T20, T21, T26, T30. Opus Medium for the rest.
  Subagents, when used, run on Opus.
- The builder owns all of the work: code, tests, downloads, install, wiring, repository,
  release. Planning is finished. Decisions D1-D15 are settled and are not reopened. When an
  assumption fails, take the fallback named beside it (or the smallest change that keeps the
  task's Verify meaningful), record it in DECISIONS.md and carry on. Stop for the owner only
  for an account authorization, a paid step, or a write into the game folder beyond what a
  task already names.
- Token economy:
  - Session start reads PLAN.md, STATE.md and LOCAL.md, nothing else. Do not re-survey the
    machine, the game or the bundle: LOCAL.md has it. Re-check a fact only when a Verify fails.
  - Open a `<PATTERN>` file only at the moment its module is ported, and only that file.
    `<SKYRIM_FORGE>` is limited to the four files LOCAL.md names.
  - No web research for anything LOCAL.md pins. Look up a format or framework rule once, at
    the task that needs it, from the primary source, and store it in `facts.json`.
  - Search before reading; read ranges, not whole large files; batch independent calls.
  - Bulk checks (the archive sweep, the material round trip, the index build) write their
    full result to a file under the forge home and print one summary line. Evidence cells
    hold counts, hashes and exit codes, never pasted output.
  - Run anything over two minutes in the background and keep working on the next task that
    does not depend on it.
  - End of a milestone: tests green, commit, STATE.md updated, stop. The next session
    resumes at NEXT ACTION without a recap.

## Risks

- Breadth: 47 tasks. Each milestone leaves a working CLI; stop points are M3, M5, M7. Gaps are reported by the tool, not hidden.
- Decompiled sources may not all recompile as imports (A2). This PC uses the official compiler and sources; the risk now sits only on the no-Creation-Kit tier.
- The Creation Kit (1.11.246) is one patch ahead of the runtime (1.11.240) and is updated by Steam on its own schedule. `doctor` reports both versions; a Creation Kit run writes into Data, so `ck` commands are dry run by default and list what they wrote.
- A natively written DX10 archive can pass every static check and still fail in game. Until an in-game load is recorded, `package` labels texture archives `load: NOT RUN`; loose files stay available.
- A game patch moves the runtime before F4SE, the Address Library and CommonLibF4 follow. Facts are keyed by runtime and `doctor` reports a mismatch instead of guessing.
- CommonLibF4 is GPL: the forge stays MIT because it never links it, but every native mod made from the template must publish source. `native new` prints this.
- Antivirus false positives on downloaded tools or freshly built DLLs. Verify hash and source before calling anything malicious; never disable a scanner from a script.
- This folder's path has `!` and spaces. Launcher tests run from an awkward folder name (T03).
- Data is deployed by a mod manager. A direct `deploy` can be reverted by its next deployment; the receipt and dry run make that visible.
- CKPE publishes under a rolling tag, so its asset name changes. It is optional and pinned by hash; a missing asset is `degraded`.
- Private paths in a public repository. `LOCAL.md` is ignored and the hygiene test covers every tracked file.
- Network limits during `tools sync`. Downloads are cached and resumable; `GH_TOKEN` is honoured when set.
